# Editorial and storyboard

## Editorial package gate

Read the approved project preference version selected by project.json and copied context references alongside the research/claims. Produce only requested editorial deliverables: video needs a script; WhatsApp is optional according to scope. Both use the same approved evidence.

Script: apply the configured sections/order or exact template, tone/persona, language, complexity/jargon, title/hook rules, pacing/duration, examples, number phrasing, ending and CTA. A hook is optional; never prepend one to a no-hook structure. Title/explanation/evidence/takeaway is a suggestion only when preferences are undecided. For video scripts include scene IDs, selected narration or silent reading holds, estimated duration, on-screen text, visual intent, and claim IDs for factual assertions. Preserve the user's exact prose/template separately from production annotations when that template excludes such fields. Keep spoken language natural. Estimate timing using the selected language/voice and then validate against actual narration or approved silent reading holds during production; word count is only a planning aid.

WhatsApp draft: use the configured template/structure, length, language/tone, emojis, bullet style, source-link format and CTA. Headline/explanation/takeaway is a suggestion, not a mandatory template. Preserve uncertainty and avoid clickbait that overstates the research. It remains a local draft; approval does not authorize sending.

Review for accuracy, evidence coverage, readability, pacing, and audience fit. Present each requested deliverable with versions, duration estimate if relevant, preference fit and unresolved decisions. Await approval of all requested items. Script-only/post-only scopes finish here; start a storyboard only for an approved video scope.

## Storyboard gate

Read [design-motion.md](design-motion.md) and [data-media.md](data-media.md). Apply the approved frame.md. Include an actual portrait style keyframe for every scene and a chart end-state/spec for each data scene.

Produce `05-storyboard/storyboard.md`. For each scene include:

- Scene ID and approximate time interval.
- Selected approved narration, captions and on-screen text; explicitly record disabled components.
- Layout, visual hierarchy, movement, transition, and explanatory purpose.
- Asset type: chart, diagram, real image/footage, typography, or generated illustration.
- For data graphics: source/claim IDs, units, time period, transformations, axis/scale choices.
- Asset sourcing/generation plan, attribution/license requirements, and voice/music plan.

Prefer visuals that explain the mechanism, comparison, or timeline. Keep a consistent brand language and deliberate pacing; avoid filling every scene with decorative effects. Label generated illustrations as such when confusion with real evidence is plausible. Do not create final narration, acquire paid assets, or launch media generation before storyboard approval.

Include a few draft keyframes if they materially help review; these are storyboard artifacts, not authorization to produce all assets. Identify the Hyperframes scene structure, required tools, proposed costs and hosted transfers. Await approval before asset production.
