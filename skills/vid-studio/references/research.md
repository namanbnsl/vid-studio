# Research, verify, and prepare content

Use the project's saved preferences and approved topic. The default outputs are a WhatsApp post and a video script. A research-only request can stop at the approved brief.

## Topic and plan

Save the topic under 01-topic/. Include audience, angle, source leads, and requested outputs. Create project.json and save its effective preferences. Get topic approval before the plan.

Save the plan under 02-plan/. Break the topic into subtopics and research questions. Define boundaries, primary sources, disputed points, date window, and data needs. Apply approved depth and time limits. Get plan approval before full research.

For daily topics, compare the plan with previous work. Keep approved scope and identify expected changes. A changed angle or scope requires new approval.

## Research and source verification

Save the brief, claim ledger, and evidence under 03-research/. Research with available LLM, search, and browser tools. Verify factual claims against actual sources. An LLM answer is not source verification.

Use primary or authoritative sources where possible. Find independent evidence for consequential, numerical, disputed, or time-sensitive claims. Confirm dates, units, and context. Separate facts, interpretation, and unknown information. Record contradictions and inaccessible sources.

Claim records contain IDs, text, source IDs, supporting excerpts, dates, caveats, and status. Use supported, disputed, or unverified status. Source records contain URLs, publisher, title, dates, and excerpts or permitted snapshots. Save evidence locally. A link alone is not a local evidence record.

For proposed charts, save original data and reproducible calculations. Include units, dates, rounding, and source metadata. Do not invent missing values. Identify forecasts and illustrative values clearly.

For daily research, record new evidence and changed conclusions. Remove duplicate findings. If nothing relevant changed, report that result. Do not manufacture a new script.

Deliver the brief, sources, verified claims, uncertainty, and proposed takeaway. Get research approval before content generation. Cross-model review is not required.

## WhatsApp post and video script

Save the outputs under 04-editorial/. Generate both by default after research approval. Use only requested outputs if the user changes scope.

Use the approved theme, language, tone, title rules, and exact structure. Apply the user's branding and examples. Keep the reusable structure consistent unless the user requests a change. Do not add a hook or CTA when excluded.

The WhatsApp post contains the approved title, concise explanation, takeaway, and source links. Apply the user's length, emoji, and format preferences. This is a local draft. Do not send it.

The script package includes these items:

- Title and ordered sections.
- Exact script text and estimated duration when applicable.
- Factual claim IDs and sources.
- Proposed visual strategy for each section.
- Proposed charts, data requirements, and source-backed values.
- Proposed real assets with source links and known usage limits.

Keep visual notes beside the script when the prose template excludes annotations. Visual strategy is a written proposal only. Do not create keyframes, acquire assets, generate audio, or render video.

Review factual accuracy, uncertainty, audience fit, language, and agreement with the approved structure. Present both requested outputs for review. Apply edits and present the new versions. Get explicit approval for each requested output.

If an edit changes facts, return to source verification. Reopen earlier review if the topic or research changes materially. Preserve reviewed versions.

## Completion and approval notes

Stop when the requested script and post are approved. Mark the project complete. Record final file paths and any unresolved research limits in STATUS.md. Do not continue to video production.

Keep approvals.md short. Record stage, reviewed file and version, actual user approval, and date. Record the reason when a stage reopens. In STATUS.md, record the current stage and next action.

Use versioned files or history copies. Do not replace reviewed content without notice. A dependency graph is not required.
